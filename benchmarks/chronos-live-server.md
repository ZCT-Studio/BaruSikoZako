# 真实客户端在线时的服务器性能对照

测试时间为 2026-11-19，Windows x64 NTFS，Intel Core i5-13420H，约 16 GiB 内存，Minecraft 26.3、Fabric Loader 0.20.1、Java 25，服务端堆上限 2 GiB。每组一次。使用一份来自用户提供的 26.2 服务端 TAR 的世界目录，先在独立 26.3 测试服启动并停服，再复制到两个独立实例。客户端使用相同的原版 26.3 安装，以真实回环网络连接，进入后等待 15 秒并保持在线。玩家保持静止，视距与模拟距离均为 2。保留原版 Watchdog 和网络超时。每个测试实例与原始文件独立。

世界依赖一些数据包和模组，测试服未安装它们。Minecraft 启动时报告缺失数据包，部分生物群系和方块回退默认值。两组使用同一份转换后的基础副本，本次结果适用于该简化运行环境。原始世界文件未被测试服修改。

Chronos 版本 1.1.3+26.x+fabric，关闭裁剪、黑名单和定时任务。其 ZIP 实现使用 JDK 默认 Deflate，字节码显示未设置压缩等级。JDK 默认使用默认压缩级别，zlib 手册将默认压缩描述为当前等效等级 6。杂鱼备份为 0.1.0-dev，配置 Zstd 3、单压缩线程及 150 ms 写入隔离预算。 [JDK Deflater](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/zip/Deflater.html) · [zlib 手册](https://www.zlib.net/manual.html)

| 指标 | Chronos，ZIP 默认 Deflate | 杂鱼备份，Zstd 3 |
| --- | ---: | ---: |
| 结果 | 完成 ZIP | 一致捕获超时，未发布快照 |
| 指令至结果 | 107.589 秒 | 0.450 秒，失败回执 |
| 备份前 MSPT P95 / P99 | 8.0 / 10.9 ms | 8.6 / 9.9 ms |
| 备份期间 MSPT P95 | 4.9–13.6 ms | 无有效窗口 |
| 备份期间 MSPT P99 | 5.2–22.2 ms | 无有效窗口 |
| 结果后 MSPT P95 / P99 | 5.0 / 5.7 ms | 8.8 / 159.0 ms |
| 服务端进程 CPU 累计 | 117.891 CPU 秒 | 1.078 CPU 秒 |
| 服务端进程读取 / 写入 | 8.436 / 7.157 GB | 0.023 / 0.025 GB |
| JVM 生命周期峰值工作集 | 892,928,000 字节 | 867,315,712 字节 |
| 已发布归档长度 | 2,937,906,236 字节 | 0 |
| 归档文件系统分配 | 2,937,909,248 字节 | 无归档 |

Chronos 的备份期间指标来自 20 次原版 `tick query`，每个查询是最近 100 tick 的分位数。表中的范围是各窗口分位数的范围，不能当作整个备份窗口的精确全局 P95/P99。杂鱼备份因隔离超时很快结束，未取到备份期间的 100 tick 窗口。其失败后查询的 P99 为 159 ms，反映包含捕获阶段的最近 100 tick，不应当直接解释为全部备份任务的 P99。

Chronos 的 117.891 CPU 秒除以 107.589 秒约为 109.6% 的单逻辑核心使用率。服务端和真实客户端均在同一台机器运行，客户端 CPU 和内存未计入表中，但会争用系统资源。进程读写是 Windows 进程 I/O 计数，并非物理盘 I/O。工作集为 JVM 从启动以来的峰值，含启动及玩家进入过程，不能解释为备份阶段新增内存。归档分配大小使用 Windows FileStandardInfo AllocationSize，临时副本的磁盘峰值未记录。

Chronos 日志显示先排空并暂停自动保存，后台复制 4,260 个文件，随后恢复自动保存并写 ZIP。ZIP 包含 4,260 条目、解压后 4,217,490,195 字节，逐条 ZIP CRC 检查通过，耗时 15.637 秒。CRC 检查覆盖归档可读性，没有证明应用层一致性，也未完成独立世界恢复验证。初次清点同时遇到 Chronos 清理临时缓存导致文件消失，ZIP 大小在清理后重新核对。

杂鱼备份日志报告 `Write isolation exceeded 150 ms`，公开任务结果为 SOURCE_UNAVAILABLE。它使用 Windows 纯 Java 暂存复制路径。退出后未发现已发布快照，捕获目录仅剩零长度锁文件。该次没有进入 Zstd 压缩，不能比较两者完成备份时的压缩速度、完整备份 CPU 或最终压缩体积。

本次是每产品一轮，结果用于定位当前大存档在线捕获的限制。要得到更稳健的比较，需要重复同等玩家负载、采集物理磁盘计数和临时磁盘峰值，并在满足同样一致性条件后对恢复内容进行验证。 [机器可读数据](chronos-live-large-raw.json) · [复跑脚本](chronos-live-large.py)
